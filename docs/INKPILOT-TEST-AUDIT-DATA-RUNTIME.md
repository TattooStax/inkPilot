# Data and runtime Android test audit

Source pinned to integrated commit `cacf2ae2dd47d3db34bd77462f6b8049ec25f70c` (2026-11-05). I read all 38 Kotlin files in `app/src/androidTest/kotlin/org/fossify/messages/inkpilot/{data,runtime}` end to end, including four fixtures/base files. The 34 test classes contain **150 `@Test` methods** (29 data-path files/117 methods; 9 runtime-path files/33 methods). At e915 the same paths had 36 files, 32 classes, 145 methods. The five new annotations are `ScheduledQueueTest` +1, `DirectReplyPreservationTest` +1, `HumanReplySmsOnlyTest` +2, and `UnqualifiedDraftGuardTest` +1. The exact method inventory below is static source evidence; Android result counts require hosted instrumentation.

Fixture codes in every row: **D** = `StudioDatabaseTestBase`: fresh UUID SQLite DB per method, drafting on, close/delete in `@After`; **M** = standalone named private Room/SQLite DB deleted in `finally`; **S** = synthetic/no persistent I/O; **J** = real app-wide scheduled verdict journal, synthetic key, no row cleanup; **G** = real app-wide settings or Studio DB, with stated cleanup; **N** = disposable emulator native provider + owned-row cleanup; **W** = test WorkManager/worker and explicitly stated cleanup. Helper `FrozenMessagesV11` creates independent old Room SQL; `StudioV1Fixture` at this source snapshot calls the current production `StudioFeatureSchema.create` despite claiming frozen v1. Isolated fix `234451e8` copies exact SQL from historical `5bc2abf` instead.

Each row names the production caller or seam under test and its decisive assertion. `Reopen` means a new repository/DB handle in the **same process** unless a separate instrumentation phase and PID assertion is stated. No data or runtime test here proves a physical carrier delivery or phone answering.

## Findings, proof limits and narrow fixes

1. **Historical fixture followed production schema.** At pinned `cacf2ae2`, `StudioV1Fixture.kt:7,95` imports and calls `StudioFeatureSchema.create` while claiming to freeze released v1. If current production SQL changes with a migration, the v1 fixture changes too and a broken migration can be hidden. Isolated commit `234451e8` copies the exact feature SQL from Git revision `5bc2abf` into the fixture. A local source check extracted both SQL blocks, asserted literal equality and no production helper reference; the existing `StudioRevisionMigrationTest` remains the meaningful Android migration proof. Android compilation remains pending.
2. **Broad WorkManager cancellation.** `SmsIntakeContinuationTest.kt:62` at the pinned source calls `cancelAllWork()` after a tagged test chain, potentially canceling unrelated work in a package sweep. Isolated commit `59a6596e` snapshots existing continuation UUIDs, asserts newly created work only, then cancels only those exact new IDs. `WorkManagerTestInitHelper` database/delegate teardown now runs even if cancellation fails. The test still has a 15-second poll plus five-second future waits; hosted runner speed may affect it.
3. **A negative send test could cross the carrier boundary after a guard regression.** `UnqualifiedDraftGuardTest.kt:75-76` at the pinned source calls production `AgentRuntime.approveAndSend` using SIM ID `1`, expecting an early `IllegalStateException`. If that early guard disappears on an emulator with active SIM 1, the test could reach an SMS send. Isolated commit `c2c8a2c8` uses impossible SIM `-1` and checks the precise model-unqualified reason. A missing model guard then fails this test before any carrier-capable subscription is selected. No real carrier send was executed by this audit.
4. **Global fixture state survives successful tests.** At the pinned source, `LegacyFirstLaunchTest.kt:129-135,218-231` changes the retired preference, recycle-bin setting, app launch count and role posture, but its `@After` removes only owned provider/Room rows. Isolated `35b882cb` restores the prior values and raw on-device posture token. `ScheduledVerdictTest` writes claims to fixed app database `scheduled-verdicts.db` without deleting test keys; `ScheduledQueueTest` and `ScheduledIdentityLifecycleTest` remove synthetic message rows but leave verdict claims. Isolated `782457ba` adds a test-only helper that records 13 methods' exact synthetic identities before mutation and transactionally removes only their claims and parts in `@After`. It does not delete the journal DB or unrelated rows. Hosted Android proof is pending.
5. **MMS callback test overstates its assertion.** `CarrierIngressTest.kt:241-301` inserts a synthetic native MMS and confirms `MmsInboundWorker` reaches `SUCCEEDED`, then cancels the work and deletes its native row. It does not assert actual carrier receipt or notification/Room-cache cleanup. Its method name says the canonical row was consumed, but the observed proof is successful worker execution against a readable native fixture. Follow up with exact post-worker state assertions and cleanup of only test-owned cache/notification entries if those are part of the intended contract.
6. **Reopen is not process death.** The `StudioDatabaseTestBase.reopen()` helper and `SmsIntakeRecoveryTestBase.reopenRepository()` close and reinstantiate a repository in the same instrumentation process. Methods describing “restart” prove durable handle reopen only. Real force-stop/PID proof belongs to separate two-phase shell tests; do not count these as process-kill coverage.
7. **Skip and privacy review.** Five `assumeTrue` calls occur in these assigned files: three emulator checks in `CarrierIngressTest` and two in `HumanReplySmsOnlyTest`; no `@Ignore` exists here. The exact-class result parser rejects assumption/ignored instrumentation status (`-4`/`-3`); base emulator/role checks throw and fail. `LocalDraftWorkerRecoveryTest` overrides qualification and uses a fake model, which proves persistence/cancellation, not LFM3 inference. All native-provider writes are guarded to a disposable emulator and use synthetic identities; the one production `approveAndSend` call is guarded by the narrowed invalid-SIM test above.
