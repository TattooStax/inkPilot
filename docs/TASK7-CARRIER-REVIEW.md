# Task 7 carrier ingress and receiver integrity — source review package

Base: Task 6 review fixes through `3a4cf33`; Task 7 source and ratchet commits `e61f3b6`, `15b64b1`, followed by this reviewer-fix commit. The local beta requires the default SMS role. No physical phone, carrier send, role, or model was touched here.

## Production contracts

- `SmsReceiver` acts only on `SMS_DELIVER` while inkPilot holds the SMS role. It commits a native SMS row and requires both positive provider and thread IDs **before** cache, notification, bridge, or agent intake. A failed insert and keyword/number/unknown-contact filters create an idempotent private SQLite record that staff can page, copy, and intentionally dismiss from Agent. If classification or private receipt fails, native inbox insertion is attempted read-only without an agent draft or automatic send; a missing thread ID still attempts a native row before a private failure receipt.
- Notification direct reply uses a unique per-message data URI, re-reads the native inbox row and exact address/thread/subscription before any send, and refuses an inactive or changed subscription. Its text is synchronously held before validation/handoff and never replayed automatically after an uncertain result. `RESPOND_VIA_MESSAGE` is parsed by scheme and recipient, persists human text even when Telephony thread lookup or saved-SIM lookup fails, and leaves an unresolved-thread record for staff without dispatch. It refuses ambiguous dual SIM selection.
- MMS callback is nonexported. `PushReceiver` remains the protected carrier WAP push entry point. The library's callback is an explicit same-package broadcast selected by task affinity (`mmslib-1.0.1` local bytecode, `BroadcastUtils.addClassName`); it accepts only `content://mms/{id}` or `content://mms/inbox/{id}`. Native MMS intake is scheduled as unique persisted WorkManager work and reads the provider before rendering notification/cache.
- Permissions-only direct-send callbacks use a different immutable PendingIntent identity for every recipient/attempt/part. Unknown exception details are not displayed in a toast. The optional bridge remains off in the local beta; Task 21 owns its provider-backed history and replay gate.

## Tests and proof limits

- `CarrierIngressPolicyTest`: positive native identity, exact SIM IDs rather than indices, canonical MMS URI and reply binding, response URI rejection. Initial focused test attempt did not demonstrate a red state because production policy source was written while the build was running; no red/green claim.
- `CarrierIngressTest` (hosted emulator qualification pending): failure and private idempotence, >16k filtered multipart, contact/journal exceptions through the production admission seam with owned native read-only provider rows, 121 filtered and 57 held entries paged/disposed, identity binding, malformed MMS rejection, and an owned native MMS fixture passed through the valid callback and WorkManager provider read. Fixture tests guard emulator hardware and delete only owned rows. AndroidTest Kotlin compiles; the tests have not executed on Android yet.
- `SmsAdmissionTest` covers classification and journal failure fallback in the same decision seam called by `onReceive`; `HeadlessReplyAdmissionTest` injects a failed thread lookup and saved-SIM lookup to verify persistence still runs. `CarrierIngressTest` reopens the actual private held store with a null thread and finds the reply through staff paging. Focused host tests and AndroidTest Kotlin compilation passed after the headless fix and receiver seam refactor. Ratchet and app identity verifier passed. Full native assembly was stopped during CMake to relieve a saturated shared host; the parent will run one combined integration gate after cherry-pick.
- A real carrier MMS download and direct reply on the OnePlus are **untested**. The library starts its own thread after broadcast completion before calling the app callback; persisted work closes the app's subsequent processing lifetime, but cannot guarantee that the library callback itself survives a process kill before it is invoked. The native provider remains the source of record for recovery.
